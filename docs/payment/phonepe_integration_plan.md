# PhonePe Payment Gateway Integration Plan

This document outlines the end-to-end implementation plan for integrating the PhonePe Payment Gateway into the Smart Citizen platform.

## 1. Database Schema & Models

We need to introduce a new `Payment` (or `Donation`) model in the backend to keep track of all transactions. 

### `payments` Table (GORM Model)
This table will store the record of every payment attempt.
- `id`: UUID (Primary Key)
- `user_id`: UUID (Foreign Key to users table, nullable for anonymous donations)
- `merchant_transaction_id`: String (Unique string generated by our backend for PhonePe - `merchantTransactionId`)
- `provider_reference_id`: String (PhonePe's internal transaction ID, populated upon success/callback)
- `amount`: Float or Integer (Amount in INR / Paise)
- `status`: String (Enum: `PENDING`, `SUCCESS`, `FAILED`, `CANCELLED`)
- `payment_method`: String (e.g., `UPI`, `CARD`, `NETBANKING` - parsed from callback)
- `donor_name`: String (To keep track of who donated, useful for tax receipts)
- `donor_email`: String (Nullable)
- `donor_phone`: String (Nullable)
- `created_at`: Timestamp
- `updated_at`: Timestamp

## 2. Backend Implementation (Go)

Following the project's modular architecture (Handler/Service/Repository), we will create a new `payment` module under `backend/modules/payment`.

Since PhonePe has recently released their **Official Go SDK (`github.com/PhonePe/phonepe-pg-sdk-go`)**, we highly recommend using the SDK over raw API calls. The SDK handles all checksum (`X-VERIFY`) generation, Base64 encoding/decoding, webhook validation, and offers built-in retry mechanisms and context propagation.

### A. Environment Variables
Add the following to `.env`:
- `PHONEPE_CLIENT_ID`: Your PhonePe Client ID
- `PHONEPE_CLIENT_SECRET`: Your PhonePe Client Secret
- `PHONEPE_CLIENT_VERSION`: Your PhonePe Client Version (e.g., `1`)
- `PHONEPE_WEBHOOK_USERNAME`: Your Webhook Username configured in PhonePe Dashboard (for Callback validation)
- `PHONEPE_WEBHOOK_PASSWORD`: Your Webhook Password configured in PhonePe Dashboard (for Callback validation)
- `PHONEPE_ENV`: `UAT` (Testing) or `PROD` (Production)
- `FRONTEND_URL`: URL to redirect the user after payment

### B. Core APIs (Endpoints)

Note: We will use the official PhonePe Go SDK (`github.com/PhonePe/phonepe-pg-sdk-go v1.0.0+`), which fully supports the V2 OAuth and Identity Manager flows natively.

1. **Initiate Payment (`POST /api/v1/payments/initiate`)**
   - **Input (DTO):** Amount, donor details, user ID (if logged in).
   - **Logic:**
     - Create a `Payment` record in the database with status `PENDING` and generate a unique `merchantOrderId`.
     - **Initialize SDK:** Initialize the SDK using `standardcheckout.GetInstance(clientId, clientSecret, clientVersion, env, shouldPublishEvents)`.
     - **Checkout API Call:** Create a `NewStandardCheckoutPayRequest` passing the amount and `FRONTEND_URL` as the `redirectUrl`.
     - Invoke `standardCheckoutClient.Pay(ctx, payRequest)`. The SDK handles the OAuth token fetching/caching under the hood.
     - **Response:** Extract `payResponse.RedirectURL` and return it to the frontend.

2. **PhonePe Webhook / Server-to-Server Webhook (`POST /api/v1/payments/webhook`)**
   - **Input:** PhonePe sends a webhook payload with an `Authorization` header containing the SHA256 hash.
   - **Logic:**
     - Extract the `Authorization` header and the raw JSON body (`responseBody`).
     - Validate the webhook using `standardCheckoutClient.ValidateCallback(username, password, authorization, string(responseBody))`.
     - Extract the `merchantOrderId` and transaction `state` (`COMPLETED`, `FAILED`, `PENDING`) from the validated response.
     - Find the payment in the DB and update its status to `SUCCESS` or `FAILED`.
     - (Optional) Trigger email notification/receipt to the donor.

3. **Check Payment Status (`GET /api/v1/payments/status/:transactionId`)**
   - **Logic:** Queries the DB for the transaction. If `PENDING`, initialize the SDK and invoke `standardCheckoutClient.GetOrderStatus(ctx, merchantOrderId)`. Extract the `state`, update the database accordingly, and return the final status to the frontend.
   - **Response:** Payment status details.

4. **Get Payment History (`GET /api/v1/payments/history`) (Admin/Citizen)**
   - **Logic:** Returns paginated payment history for a user or admin.

## 3. Frontend Implementation (Next.js / React)

### A. Donation Form (`PaymentInfo.tsx` / `DonationPage.tsx`)
1. Create a form where the user can enter the donation amount and their details (if not logged in).
2. On form submission, call the backend `POST /api/v1/payments/initiate` endpoint using Zustand or direct fetch.

### B. Redirection to PhonePe
1. The backend response will contain a `redirectInfo.url`.
2. Redirect the user's browser to this URL using `window.location.href = response.redirectInfo.url`.

### C. Return & Status Pages
PhonePe will redirect the user back to your site after the payment (e.g., `/donation/status?transactionId=xyz`).
1. Create a `PaymentStatus` page component.
2. When the page loads, extract the `transactionId` from the query parameters.
3. Call the backend `GET /api/v1/payments/status/:transactionId` to determine if it was successful.
4. Render a Success UI (with a downloadable receipt option) or a Failure UI (with a "Try Again" button) using the project's standard UI components (`Card`, `Button`, etc.).
